# Data Schema & Verification Rules

All published values are stored as JSON in this directory and rendered to static HTML by
`scripts/build.py`. **Nothing is typed directly into the HTML.** This guarantees that every
published number traces back to a record with a source URL and a capture timestamp.

## Files

| File | Contents |
|---|---|
| `fdic.json` | FDIC deposit-insurance rules and ownership-category limits |
| `benchmarks.json` | FDIC monthly National Rates & Rate Caps (competitiveness benchmark) |
| `accounts.json` | Institutions and their savings products |
| `bonuses.json` | Account-opening bonuses and promotional rates |
| `flags.json` | Irregularities and unverified items (published on Flagged for Review) |
| `returns.json` | **Derived** — generated by `scripts/build.py`, not hand-edited |

## Field-level verification object

Every sourced value is wrapped in an object:

```json
{
  "value": 3.75,
  "unit": "percent_apy",
  "status": "verified",
  "source_url": "https://www.cit.com/cit-bank/resources/products-and-rates",
  "source_type": "official",
  "source_org": "CIT Bank (division of First-Citizens Bank & Trust Company)",
  "as_of_stated": "2026-07-01",
  "retrieved_utc": "2026-10-22T00:00:00Z",
  "note": "Balances of $5,000 or more"
}
```

### `status` values

| Status | Meaning |
|---|---|
| `verified` | Read directly off the institution's own website, rate sheet, or disclosure PDF, or off a `.gov` source. `value` is populated. |
| `unverified` | The official page exists but the value could not be read (ZIP/cookie gating, JavaScript-only rendering, product unavailable in region). `value` **must be `null`**. A matching record exists in `flags.json`. |

### Hard rules

1. `value` is `null` whenever `status` is `unverified`. No estimates, no averages, no carry-over
   from a previous month, no aggregator figures.
2. `source_type` must be `official`. Permitted domains: the institution's own domain, `fdic.gov`,
   `api.fdic.gov` / `banks.data.fdic.gov`, `federalreserve.gov`, `treasury.gov`,
   `apps.apple.com`, `play.google.com`.
3. `as_of_stated` is the effective date **printed by the source itself**. If the source prints no
   date, the field is `null` and only `retrieved_utc` is shown.
4. Derived numbers (interest projections) never claim a source. They carry `"derived": true`
   and the formula is published on the Methodology page.

## Derived-return model (`returns.json`)

```
ending_balance = principal * (1 + APY) ** (days_held / 365)
interest       = ending_balance - principal
```

Assumptions, all published on the site:

* Account opened **2026-10-22** (today, UTC) — used for every maturity date.
* APY is held constant for the whole horizon. Every savings APY here is **variable** and can
  change the day after opening; projections are therefore illustrative, not promises.
* No deposits, no withdrawals, interest left on deposit.
* No fees deducted. Fee terms are published separately per account.
* 365-day year; no leap-day adjustment inside the exponent (calendar maturity dates **do**
  account for leap days).
* Promotional/relationship APYs are modelled only where the promotion's duration is stated by
  the institution; otherwise the standard APY is used and the promotion is listed separately.
